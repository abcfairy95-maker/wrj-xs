# 固定卡扣辅助布线原型：实现与交付状态

本分支是研究原型，不是生产验收版本。当前实现用卡扣约束修正分叉，尚未实现卡扣选择、方向和分叉位置的全局联合规划。

## 入口与数据

核心入口为 `route.py`；`harness_plan` 为数据、地图、寻路、拓扑、平滑、输出与验证模块。`view_result.py` 生成HTML查看器。已有 `environment` 数据模块保留。

```sh
pip install -r requirements.txt
python route.py --case <case_directory> --device cpu --voxel 30 --out <result.json>
python route.py --case <case_directory> --input-file <absolute_input.json> --device cpu --voxel 30 --out <result.json>
python view_result.py --case <case_directory> --result <result.json> --out <view.html>
```

案例目录需要原有 `input/input.json` 与STL文件；替换输入时仍从case目录加载环境。输入与STL、客户结果不包含在仓库中。CPU基础依赖见requirements.txt；GPU另需安装匹配机器CUDA环境的PyTorch，测试需pytest，带GPU路径的测试也需PyTorch。原型在CUDA不可用时可能使用CPU后端，不能把device=gpu标签当作真实GPU运行证明。

## 实际算法

1. 在固定体素地图上计算长度与贴面偏好代价。起终点最短路代价的MST用于终点接入顺序。
2. 首条路径形成初始骨架，后续终点在已有路径节点上选择接入位置；检查末端分支长度、分叉间距，已连接4段的节点不再接入。
3. 卡扣位置及方向固定。沿归一化dir设置两侧辅助点，本案例各15mm，接入路径并禁止卡扣分叉或悬挂折返。
4. 整链平滑共享节点与切向，输出分段几何来自同一条最终中心线。
5. 用最终沿线弧长检查l1/l2/l5。违规分叉候选被排除后重建，卡扣本身不移动；此次启用卡扣集合保持不变。
6. 输入候选卡扣按实际网络弧长筛选间距冲突；未启用原因写入metadata。正式输入l3=100mm，不沿用此前60mm实验。

候选来自已有路径，接入顺序会影响结果。重复候选反馈不是全局最优求解，也不保证任意输入下总能找到满足所有要求的结构。候选不可达不等于物理不可达。

## 最新代表案例与验证

C07输入由三终点案例仅追加19个原始终点形成；原3个终点顺序、15个候选卡扣、环境、参数均不变。CPU、体素30mm。

| 指标 | 分叉距离修正前 | 最新结果 |
|---|---:|---:|
| 终点连接 | 22/22 | 22/22 |
| 独立分叉 | 15 | 14 |
| 覆盖客户卡扣 | 10 | 同样10个 |
| 通过当前穿行及距离检查 | 8 | 10 |
| REF-000距分叉 | 32.09mm | 47.99mm |
| REF-012距分叉 | 38.97mm | 82.20mm |
| 本地CPU端到端时间 | 16.66s | 约41.8s |

最终版本真实结果检查：22个终点、卡扣原始位置方向、段端点与拓扑引用、分段拼接和整链几何一致；l1/l2/l5与最多4段无违规。独立核对全部经过卡扣的harness，卡扣处最大方向角误差约0.00000085度。以上不代表全几何验收。

早期三终点C07有2个分叉，不能与22终点结果直接对比。旧warmup C07为22请求/21连接、16分叉、3mm体素，也不是本轮同条件基线。
